# stage 24：短期目标 —— 11 fps 且画面完整

## 已知的两条路（都只满足一半）

| 路径 | 帧率 | 画面 | 原因 |
|---|---:|---|---|
| 产品路径（客机 CA 合成 → 传面板） | 2–3.3 fps | ✅ 完整 | 客机每帧 245 ms：CA 184 ms + readback 60 ms |
| 宿主回放记录流（`NO_PANEL=1`） | **10.91 fps** | ❌ 缺 dock/Search/右下 | 那些内容不进记录流 |

目标：把「10.9 fps 的回放路径」补成**画面完整**。

## 关键假设（要先验证）

**缺失内容是静态的**：dock 背景、Search 胶囊、右下角背板在一次会话里基本不变，
变的是图标/文字/widget（这些**在**记录流里）。
→ 若假设成立：把缺失区域**只传一次**，之后每帧只回放记录，帧率仍 ~10.9，画面完整。

## 步骤

### 1. 侦察（exp，1–2 发）
- 同一时刻取两张：**完整面板**（产品路径的 panel）与**回放帧**（`NO_PANEL=1` 的输出）；
- 计算像素差 → 得到「回放缺失掩码」；
- 报告：掩码的 bbox、面积占比、字节数（原始/565）、**跨 3 帧是否稳定**（逐像素比较）；
- 若掩码稳定且面积 <25% → 静态补丁方案成立。

### 2. 静态补丁通道（code）
- 客机在首帧（或掩码变化时）把缺失区域的像素**一次性**发给宿主（565 或 RGBA，按 bbox 裁剪）；
- 宿主在回放结果之上/之下合成这块补丁（顺序按 z：dock 在图标下方还是上方，需要实测定）；
- 之后每帧只发记录流，不再发像素。

### 3. 验收（exp + 咱）
- **fps ≥ 10**（guest 时钟，静止与滚动各一段）；
- **画面判据**：dock 通栏 4 图标、Search 居中、右下不黑、≥5 个 app 名称可读；
- 截图存档与产品路径并排比对（人眼可辨无差异）。

## 风险与退路

- 掩码**不稳定**（例如 dock 有动画/阴影随滚动变化）→ 退化为「区域补丁每帧发送」，成本 = 面积 × 1 帧像素，若 <25% 面积用 565 约 0.3 MB ≈ 66 ms/帧 → 只能到 ~6 fps；
- 合成顺序错 → 画面出现遮挡错误，需要在宿主侧调 z 顺序；
- 记录流本身对某些帧不完整（之前 `decrec2` 看到有的帧只画 310×310）→ 那部分用补丁覆盖。

## 不做

- 不再优化传输（已证伪：push 7 ms、占帧 2–5%）；
- 不动 virtio-gpu A4/virgl（保留为长期路线）。
