`after empty send` → **空 header 的 `mach_msg` 是崩点**（不是 host_info 阻塞）。**

## 判断

- **host_info 链路正常**：BASIC/LOAD 成功返回（`kr=0`），`host_statistics64`
  也成功 → host port MIG/内核 server 对 guest 探针完全可用。
- **崩点在空 header 的 `mach_msg`**：`before empty send` 后无 `after`，进程死在
  那次 `mach_msg`（可能 send 到无效 reply port 触发异常）。
- 这解释 ext10：probe1 在 `mach_host_self` 之后的下一步正是这条空 send，所以
  ext10 也死在这里，**不是 host_info 阻塞**。
- 对 extension 的意义：extension 不在 host_info 上卡（链路正常），其 CheckIn
  缺失仍需回到 launchd/xpcproxy 的 exec 阶段（ext9 的 `exit(78)`/`reg_app` 缺失
  也需独立修）。
