# S22 ext4 — 新内核起不来（unexpected kernel layout）

**结论：未跑到 guest，未验证 `hakios: host_info`。** 宿主新编的 `hakios-kernel`
（md5 `0847e9566ee9eb7be7e3200547d9cad2`，15,902,536 B，`strings | grep -c
'hakios: host_info'` = 2）经 `run-darwin.sh` 用 `mkpayload.py` 重新生成 payload
（`payload entry 'kernel' size f2a748` 对得上），但 loader 报：

```
kernel va 0..1314000 entry 0
unexpected kernel layout
```

—— 新内核 Mach-O 是 `va 0..0x1314000, entry 0`；旧内核是
`kernel va fffffff007004000..fffffff0082f8000 entry fffffff00745e4a8`。

## Recipe

- system `8bf5f838…`；root `/tmp/root-w15.apfs` `785bcbac…`（cell3）；
- kernel `hakios-kernel` md5 `0847e956…`，15,902,536 B，trace 串 2 行；
- `XCMD="glwire_local=1 launchd_disable_all_timeouts=1 hakios_host_info_trace=1"`；
- `HOST_ENV="GLWIRE_NO_PANEL=1"`；`MINFRAMES=999999 UI_GRACE=400 MAXSECS=1120`；
- payload 非旧：`run-darwin.sh` 每次 boot 用新 kernel 重生成。

## 判断

- **不是 payload 旧**：kernel entry size 与 15,902,536 B 一致；
- **是新 kernel 布局问题**：`va 0..1314000 entry 0` + `unexpected kernel layout`，
  很像 `ld64.lld` 链接参数与旧 `ld64` 不同（丢了 `__TEXT` 的 `vmaddr`/entry）。
- 需要 code 用与旧内核一致的 `ld64`/链接参数重建，让 `kernel va` 回到
  `fffffff007004000..` 这一类高地址布局。
- ext4 预算未消耗内容（未到 guest）；等修好的 kernel 再跑。
