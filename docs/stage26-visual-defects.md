# 画面缺陷：黑块闪烁 / 文字虚线 / 应用突然变大（2026-11-20）

来源：主人看 `s28-ux9`、`s28-ux11` 录像后报的问题。三个现象都不是“卡顿”，是**回放合成**的问题。

## 一、黑块闪烁（时钟秒针位置闪黑）、大面积黑块
- 现象：时钟秒针、图标、文字下方在刷新位置出现黑块；滑动/启动过渡时出现大片黑区。
- 根因（已知）：我们的远程路径是**脏矩形回放**——guest 每帧 `glClear` 整个 drawable，然后只重画变化区域；
  真实设备上“没重画的地方保持上一帧”，但**宿主回放会把 clear 照做**，于是宿主 framebuffer 被清空、未重画区域变黑。
  静态补丁只是把“静止主屏”的下半屏补回去（`GLWIRE_PATCH_MIN_COVERAGE`），一旦画面活跃（覆盖率高于阈值）就不贴，
  黑块立刻露出来。这解释了“时钟位置闪黑”和“大面积黑块”。
- 修复方向（已实现，待验证）：宿主侧加 `GLWIRE_SKIP_CLEAR=1`——**不重放颜色 clear**，让帧累积在上一帧之上，
  与真实显示器行为一致。代码：`tools/glwire/dispatch.inc` 的 glClear 分支 + `host_glwire.c` 的 `host_skip_clear`。
- 验收：同一操作序列（`rc.ux` 三轮 burst）下录像里不再出现黑色空洞；静止时画面不被清空；必要时再把 `PATCH_COV` 调低。
- 风险：如果某帧本该清成黑色（例如切到深色背景的应用），会残留旧内容 → 需要给“整屏清为纯色”的情况留例外（第二条）。

## 二、文字下方的虚线（下划线）
- 现象：图标名的下划线是虚线/断点，不是实线。
- 现状：属于“文字渲染保真度”类问题，一直在判死清单里（`文字虚线`），原因是字形/下划线栅格化路径（glyph 采样、atlas 上传）；
  它与帧率无关，纯观感问题。
- 安排：排在黑块修复之后（本周内给一次专项定位：抓一条带下划线的 `glDrawElements`/atlas 记录，和真实 iOS 对比像素）。
  若定位成本高，则在需求文档里交给外部（Claude）处理。

## 三、News 应用“突然变大”
- 现象：某一阶段 News 的图标/内容被放大（见主人截图）。
- 待查：疑似应用窗口的 **scale/transform** 状态在回放里没有被重置（上一个应用的 viewport/变换残留），
  或 launch 动画结束时没有收到“恢复”序列。需要一次带 News 的复现（打开 News → 截图 → 与真机比例对比）。
- 计划：复现一次并抓该帧的 record 流（`GLWIRE_DUMP_FRAME`），比对 transform 调用。

## 五、2026-11-21 00:30 新证据：label FBO 里是**实线**，屏幕上是虚线
同一次运行（`p1-fix2`，`GLWIRE_LABEL_DUMP=1`）dump 出的 label FBO（750×200）：
- 文字占 rows 0–60；
- **rows 61–63 是一条 x=24..125 的连续实线**（102 px 宽、3 px 高，见 `1-label-2-fbo-5-750x200.bgra`）。

也就是说：**guest 渲染 label 时画的是一条实线下划线**（不是虚线），而最终屏幕上看到的是虚线。
→ 虚线是在 **label FBO → 屏幕** 这一步被引入的（缩放/采样：750 与 1125 之间的非整数比例 + NEAREST 采样，
   3 px 的实线被 2/3 或 1.5 倍采样打散成 2–3 px 的点），而不是字形或 tile 内容本身。

下一步（一次运行即可定论）：
1. 用 `GLWIRE_SAVE=<dir>` 或让 label FBO dump 与 `GLWIRE_DUMP_AT` 在**同一帧**触发；
2. 把屏幕上的带与同帧 FBO 的实线逐像素对齐（缩放矩阵可反推）；
3. 若确认是采样，修法二选一：① 该 pass 改 `GL_LINEAR`；② 直接让 guest 不画这条下划线（如果它本就不该存在）。

## 六、2026-11-21 02:30 决定性对照：**原生 3x 渲染时没有这条线**
- 用 `fbscale=3` 跑一发（`p1-scale3`，display 1125×2436 = panel 1125×2436，1:1 无缩放）：
  guest 起机正常，主屏标签（Health / Wallet / Settings / TV / Podcasts / App Store / Maps）**完全没有任何下划线/虚线**，字也干净。
- 而 `fbscale=2`（display 750×1624，内部 2x 渲染）时，同一批标签下面出现 1–2 px 的虚线段。
- 结合上一节（label FBO 里是**3 px 实线**）：这条“下划线”是 **2x 渲染路径的产物**——可能是文本渲染时多画了一条被压扁到 1–2 px 的副本（内容像被横向压扁的字形片段），
  在 3x 路径里根本不画。
- 结论：**它不该存在**（真机/3x 都没有）。因此修法优先“**在 2x 路径上不画/清掉这条带**”，而不是“把虚线补成实线”。
- 已定位到的像素形态（`p1-fix2` 的 750 宽帧）：带在标签文字下方 1–3 px 处，共 1–2 行，由 1–4 px 的短段组成、跨度 30–320 px，正下方紧接图标；
  用“短段数 ≥4 且填充率 0.2–0.85”可以把它和文字行区分开（文字行的段更长、且上方有字身）。
- 下一步：在 host 的 label pass（scissor 切换到标签区域时）读回该区域、按上面的形态擦掉这条带（或直接在 guest 侧 2x 路径跳过这次绘制），再跑一发验证。
