# S22 ext9 — 探针 boot（标准配方，到 UI 但探针未跑）

**结论：ext9 用标准配方（rc.vtop + EXTRA + RC_JOBS）到了 UI
（`end=ui ui=660s ui_bytes=308085 guestframes=52 hostframes=1187`），镜像内
`/etc/rc.jobs` 确认是探针内容，`/bin/hostinfo_probe`（50,120 B）也在，但串口
`hostinfo:` **0 次**、`hakios: hostport` 0、`hakios: host_info` 0 →
**demo job 没跑到探针**，本发没有 OK/BLOCKED/KR 三选一。**

## 配方

- root `/tmp/root-ext9.apfs`（5.7M，md5 `10b2e125c48243d32a6cf905bd8dcc54`）：
  `EXTRA=/host/iosvm/logs/s22-ext/probe-bin/hostinfo_probe`
  `RC_JOBS=/host/iosvm/guest/rc.jobs.hostinfo`
  `PREBUILT=1 GL=1 GLREMOTE=1 CONFIGD=1 RC=rc.vtop ./build.sh`；
- 内核 `hakios-kernel` md5 `1f8c489f2ca93043d53b20aa04739109`
  （`__TEXT=0xfffffff007004000`、`hakios: host_info`×2、`hakios: hostport`×1）；
- system `8bf5f838…`；`QEMU_SMP=1 ZERO_RAM=1`；
- `XCMD="glwire_local=1 launchd_disable_all_timeouts=1 hakios_host_info_trace=1 hakios_hostport_trace=1"`；
- `boot-measure.sh ext9 /tmp/root-ext9.apfs 1100 --no-panel`（`UI_GRACE=400`）。

## 判断

- `rc.jobs`/探针都进了镜像，但 demo job 没执行探针 → `rc.vtop` 走 stage0 +
  自己的 job 列表，`com.hakios.demo` 可能没被加载（stage0 也有 fill_panel 缺失）。
- 本发**不能**给 OK/BLOCKED/KR 结论；不是探针本身的问题。
- 下一步：把探针挂到 rc.vtop 实际会执行的 job（或直接进 `/etc/rc` 命令流），
  再跑一发（1100s）。
